Does the build cache work with Kotlin and Android builds?

For Kotlin on the JVM, yes. In our runs Gradle took the Kotlin compile tasks and the test task from FosterStack Cache instead of running them again. We are still measuring Android.

The short answer for Kotlin

  • Kotlin compiles came from the cache. In a repeat build, compileKotlin and compileTestKotlin were restored, and so were compileJava for the Java file in the same module and the test task.
  • The jar tasks ran every time. They were not restored in any of our builds.
  • After a change inside a method, only that module's Kotlin compile ran again. The module above it still restored its Kotlin compile, but its test ran again.
  • After a new public function, the Kotlin compile ran again in both modules. The Java compile in the changed module ran too, and so did the test.

ANDROID-PENDING: what Gradle restores in an Android build, measured on a GitHub-hosted machine, goes here.

What to do

Our advice, not a test result:

  • Look for FROM-CACHE on the compile and test lines. That is where a Kotlin build shows its hits. See how to measure your hit rate.
  • Do not count the jar tasks as misses. They ran every time in our builds, even when everything else was restored.
  • Keep the Kotlin plugin version and the Java version the same on laptops and CI, so entries can be shared. If the hit rate is low, see why the Gradle hit rate is low.

How we checked

We built a small Kotlin project twice in each of three cases, always on a new empty FosterStack Cache server. Build 1 stored the results. Build 2 used a fresh copy of the project. This table shows build 2.

TaskNothing changedBody change in coreNew public function in core
:core:compileKotlinfrom cacheranran
:core:compileJavafrom cachefrom cacheran
:app:compileKotlinfrom cachefrom cacheran
:app:compileTestKotlinfrom cachefrom cacheran
:app:testfrom cacheranran
:core:jar and :app:jarranranran

What: Gradle 9.8.0, the Kotlin Gradle plugin 2.4.21, Temurin 21.0.12.1, FosterStack Cache 0.2.1, on a Mac (arm64). Two modules: core has a Kotlin class and one Java file, app has a Kotlin class and one test and uses core. The command was gradle build.

How: every build used a fresh copy of the project and Gradle's local cache was off. One Gradle home was shared for downloads (the plugin and the test libraries), and it was filled first by a build with the cache off. The tasks without a test source (:core:test and the empty Java compile in app) had nothing to run and are left out.

Not tested: Android, Kotlin Multiplatform, kapt or KSP, Compose, Maven, Linux. We make no claim about build times.
