How many builds can use one cache server at once?

In our runs, one FosterStack Cache server handled 8 builds at once and every build succeeded. It refuses an upload only when too many uploads arrive at the same moment, and the limit is 32 by default.

The short answer

  • Up to 8 builds at once worked. All 39 builds in our main run ended with BUILD SUCCESSFUL. None printed a cache warning.
  • The server stayed small. Its memory peaked at about 16 MiB under the builds. It peaked at about 23 MiB under a burst of 100 uploads of 1 MiB each.
  • Uploads have a limit. By default the server takes 32 uploads at a time. An upload past the limit gets a 429 with Retry-After: 1, and nothing is stored.
  • A refused upload costs one build its cache, not the build. In our run, Gradle printed one warning, switched the remote cache off for the rest of that build and still ended with BUILD SUCCESSFUL. The next build was normal.
  • Reads and repeat writes were safe. No read failed. Two uploads of the same entry at once left one complete entry. A reader got 404 while a slow upload was running, never half an entry.

What to watch

Our advice, not a test result:

  • Watch the refused-upload counter. It is fscache_http_requests_total{method="PUT",status="429"}. In our build runs it stayed at 0. If it climbs, uploads are being refused.
  • If it climbs, count how many jobs upload at the same moment. Many CI jobs that finish together and upload large outputs are the likely cause. Our builds uploaded small entries, 13 of them in about 36 KB, and none was refused even with the limit set to 1.
  • The limit is a setting. It is FSCACHE_MAX_CONCURRENT_UPLOADS, and 0 turns it off. We tested 8, the default of 32 and 0. We did not test what 0 does on a small machine.
  • Keep watching memory and server errors too. See is my build cache server healthy and how do I know my build cache hit rate.
  • Size the machine for the disk, not for the builds. See how big a server a build cache needs and can I run the build cache on a small VM or laptop.

How we checked

Builds at once. We started the server empty and ran 1, 2, 4 and 8 identical builds at the same moment. Then we ran the same number again against the filled server.

With identical builds, several of them uploaded the same entry. The server took every upload and kept one copy of each entry. Every warm build restored all four of its compile tasks from the cache.

Changed and unchanged builds together. We filled the server with one build, then ran 4 builds with changed code and 4 with unchanged code at the same moment. All 8 succeeded. The server held 13 entries before and 29 after, which is 4 new entries for each changed build. Each unchanged build restored all four compile tasks. Peak memory was 15.8 MiB.

Reads were never refused. A read returned 200 for every entry that was stored and 404 for every entry that was not, including those whose upload had been refused.

A refused upload in a Gradle build. We set the limit to 1 and held the only upload slot open with a slow upload. A build that stored entries during that time printed one warning, Could not store entry ... response status 429: Too Many Requests, then The remote build cache was disabled during the build due to errors. It ended with BUILD SUCCESSFUL, and Gradle did not retry. The build after it, with the slot free, printed no warning. We also ran 8 builds that all stored at the same moment with the limit at 1. All succeeded and none was refused.

What: FosterStack Cache 0.2.1 on a Mac (arm64, 10 CPUs, 16 GiB), no password. Gradle 9.8.0 with Java 21, a four-module project, compile tasks only. Each build used a fresh copy of the project, a new Gradle home, no reused daemon and the local build cache off. Memory is the server process only, sampled every second for builds and every 0.2 seconds for the direct requests.

Limits: the Mac was heavily loaded by other work, with a load average from about 8 to 180 during these runs. So we report counts and outcomes, not times, and nothing here says how your hardware will behave. One run for each row. Not tested: Maven, more than 8 builds at once, uploads larger than 8 MiB, Linux, Docker and Kubernetes.
